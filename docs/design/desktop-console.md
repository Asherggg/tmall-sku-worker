# 天猫运营工作台桌面与应用 UX 设计

## 1. 设计目标

本设计把 Tauri 2 应用定位为面向店铺运营的本地工作台。启动后首先呈现运营桌面，用户从快捷方式启动具体应用；登录会话、Worker、任务和审计由工作台统一提供。v0.1.29 包含 `SKU ID 重建`和`新增花型`两个持久应用实例，分别承载两阶段 SKU ID 重建和 Excel 明确组合新增流程。

批次中的不同商品最多两路准备/回读，实际提交请求保持串行；天猫页面和浏览器窗口不是主界面；登录使用系统 Edge 专属 Profile 且不附加 Playwright，登录后才建立 CDP 连接，正常任务通过共享登录态的纯 HTTP 接口完成。

设计优先级：

1. 让用户在任何写入发生前看到清楚的范围、风险和确认闸门。
2. 让线上批量任务可扫描、可追踪；失败时能定位到商品和阶段。

> v0.1.29 实现约束：工作台桌面提供 `SKU ID 重建`、`新增花型`、`任务中心`、`浏览器会话`快捷方式；两个业务应用只提供线上模式并使用各自确认闸门。新增花型只处理 Excel 明确列出的组合，保留全部原 SKU 和 ID，每商品至多一次提交。旧渠道只在零写入阻断任务中显示 `1/2` 人工选择，不允许批次预填或自动映射。线上任务启动后必须连续完成回读；最小化或关闭应用窗口不能停止 Worker 任务。Tauri host 使用 Windows Job Object 回收 bundled Worker，NSIS 升级前也会按完整路径结束安装目录下遗留的 Worker 子进程；实时库存不参与最终快照一致性判定。
3. 让“已完成”必须有服务端回读证据，而不是只代表请求返回 200。
4. 让登录凭据留在专用 Profile 中，界面不展示 Cookie、Token 或完整敏感请求体。

## 2. 视觉与窗口基线

### 2.1 窗口

- Tauri 原生窗口默认 `1280 x 820`，最小 `1040 x 680`；允许最大化。
- 初始画面是工作台桌面，不自动打开 SKU 应用。
- 桌面快捷方式支持鼠标双击和键盘 Enter 启动；单击只选择，不触发应用行为。
- SKU 应用以工作台内部窗口打开，支持拖动、调整大小、最小化、最大化、还原和关闭。
- SKU 重建和新增花型各自只保留一个实例；两个实例可同时打开，通过任务栏切换层级与可见性。
- 任务中心和浏览器会话快捷方式定位到 SKU 实例；新增花型内部提供自己的任务队列和浏览器会话视图。
- 应用窗口隐藏后模块实例继续保留，SKU 导入草稿、新增花型 Excel 预览、当前视图和 Worker 任务不会因窗口可见性变化而丢失。
- 底部任务栏提供显示桌面、运行应用切换、Worker/会话状态和时间。

### 2.2 视觉语言

- 以中性灰白背景、深色正文和少量蓝色主操作为基础；成功使用绿色、警告使用琥珀色、失败使用红色。
- 不用大面积渐变、装饰性卡片或营销式英雄区域；页面服务于扫描和反复操作。
- 卡片只用于重复的统计项、任务行和真正需要框定的工具；页面分区采用无框布局。
- 图标使用 Lucide（`Play`, `Pause`, `Upload`, `ShieldCheck`, `AlertTriangle`, `ExternalLink`, `RefreshCw`, `Eye`, `FileText` 等），图标按钮提供 `aria-label` 和悬浮提示。
- 状态不能只靠颜色表达：颜色之外必须同时显示文字和图标。
- 正文 14px、表格 13px、页面标题 20px；不使用随视口缩放的字号，字间距保持 0。

```text

│                                                                              │
│ [SKU ID 重建] [新增花型] [任务中心]                                           │
│ [浏览器会话]                                                                 │
│                                                                              │
```

两个应用窗口内部都保持左侧导航、顶部页面状态和内容区。工作台层不复制业务操作，只聚合应用入口和全局状态。关闭内部应用窗口只返回桌面；退出 Tauri 主窗口才结束本次桌面会话。

## 3. 信息架构与路由

| 路由 | 页面 | 主要任务 |
|---|---|---|
| `/overview` | 总览 | 查看登录、Worker、批次和待处理风险 |
| `/import` | 批量导入 | 解析 CSV/粘贴文本、校验、最多展开 10 个商品的预览、创建线上批次 |
| `/tasks` | 任务队列 | 过滤、暂停、继续、删除任务、人工核对后解除未决写入锁、进入详情 |
| `/tasks/:batchId/:itemId` | 任务详情 | 查看阶段时间线、SKU 映射、字段差异和复核动作 |
| `/browser` | 浏览器登录 | 查看 Profile、打开正常有头的专属 Edge、检查登录态 |
| `/audit` | 审计记录 | 按批次/商品/结果查询和导出脱敏记录 |
| `/pattern/import` | 新增花型导入 | 读取 `.xlsx`、八列校验、按商品汇总、预览源行和创建线上批次 |
| `/pattern/tasks` | 新增花型队列 | 查看明确组合、已有/新增数量、阶段、错误和时间线 |
| `/pattern/browser` | 新增花型浏览器会话 | 复用工作台专属 Edge 登录状态 |

导航项旁显示未读数量：两个任务队列显示各自活动任务数，审计记录显示待人工复核数。路由切换、最小化和关闭内部应用窗口不会卸载模块，因此本次桌面会话中的草稿和当前页面保持不变；退出 Tauri 主程序后的草稿持久化属于后续能力。

## 4. 全局交互与状态约定

### 4.1 状态标签

| 状态 | 标签文案 | 图标 | 颜色 | 允许动作 |
|---|---|---|---|---|
| `live` | 线上 | ShieldCheck | 琥珀 | 需确认后开始 |
| `queued` | 排队中 | List | 灰 | 取消 |
| `reading_snapshot` | 读取快照 | Download | 蓝 | 安全暂停 |
| `temp_submitting` | 临时提交 | Upload | 琥珀 | 等请求结束后暂停 |
| `temp_verified` | 临时已校验 | Check | 蓝绿 | 继续/暂停 |
| `restoring` | 恢复原数据 | RotateCcw | 琥珀 | 等请求结束后暂停 |
| `final_verifying` | 最终回读 | SearchCheck | 蓝 | 安全暂停 |
| `pattern_preparing` | 准备花型 | FileSearch | 蓝 | 只读规划 |
| `pattern_submitting` | 提交花型 | Upload | 琥珀 | 等待请求结果 |
| `pattern_verifying` | 回读花型 | SearchCheck | 蓝 | 只读回读 |
| `succeeded` | 已完成 | CheckCircle2 | 绿 | 查看详情 |
| `failed` | 失败 | XCircle | 红 | 查看错误、重试 |
| `needs_manual_review` | 待人工复核 | UserRoundCheck | 红橙 | 打开详情、确认状态后继续 |
| `paused` | 已暂停 | PauseCircle | 琥珀 | 继续、取消 |

### 4.2 通知

- 非阻塞提示使用右上角通知栈，最多显示 3 条，自动消失时间不超过 6 秒。
- 写入结果、登录失效、未知响应和人工复核必须使用持久通知，直到用户打开对应任务。
- 通知中只显示脱敏的 `itemId`、阶段和错误码；完整响应放在任务详情的“接口结果”折叠区。

### 4.3 统一加载、空和错误模式

- 加载：显示与最终布局相同的骨架行，不使用全屏旋转遮罩阻塞已可用内容。
- 空列表：显示短标题、下一步主按钮和可选的导入/刷新图标；不放长篇说明。
- 错误：显示错误码、可执行动作（重试读取、打开登录窗口、导出诊断）和 `requestId`；不显示凭据。
- 离线/Worker 不可用：顶部红色状态条，禁止创建线上计划，允许查看本地历史。

## 5. 页面设计

### 5.1 总览 `/overview`

#### 布局

```text
┌───────────────────────────────────────────────────────────────────────┐
│ 总览                                             [导入清单] [刷新]    │
├──────────────┬──────────────┬──────────────┬──────────────────────────┤
│ 登录状态     │ Worker       │ 当前批次     │ 待人工复核               │
│ ● 有效       │ ● 隐藏运行   │ 12/30        │ 2                        │
├──────────────┴──────────────┴──────────────┴──────────────────────────┤
│ 当前任务                                                             │
│ itemId        阶段                 进度       用时       状态          │
│ 828872681901  恢复原数据并提交      1/2 SKU    18s        处理中        │
├───────────────────────────────────────┬───────────────────────────────┤
│ 最近批次                              │ 操作                           │
│ 批次 ID / 创建时间 / 成功 / 失败       │ 打开队列 / 查看复核             │
└───────────────────────────────────────┴───────────────────────────────┘
```

统计项只呈现可行动的数量；点击统计卡直接带筛选进入任务队列。当前任务展示阶段和安全暂停按钮，不能在总览中直接触发线上重试。

#### 状态变体

- 未登录：统计卡替换为“需要登录”，主按钮为“打开登录窗口”。
- 无批次：显示“还没有批次”与“导入清单”按钮。
- Worker 断开：保留历史统计，当前任务区域显示连接错误和“重新连接”。
- 有人工复核：复核卡使用高对比度警示，并显示最早一条 `itemId`。

### 5.2 批量导入 `/import`

采用四步向导，顶部步骤条固定：`输入` -> `校验` -> `分组预览` -> `创建批次`。每一步可返回，但不会悄悄修改已锁定的批次。

#### Step 1 输入

- 主区域默认为多行商品 ID 输入，每行一个 `itemId`，无需表头。
- 保留 `.csv` 兼容入口；CSV 使用 UTF-8 和表头 `itemId,skuId,expectedSkuCount`。
- 解析后显示商品总数；仅输入 `itemId` 时，SKU 数显示“待读取”，由商品快照补全。

#### Step 2 校验

简易输入的校验列为行号、`itemId`、校验结果和动作；CSV 模式再展示 `skuId` 和预期 SKU 数。错误行使用左侧红色标记和文字原因：空 ID、非数字、重复行、无法分组。提供单行移除和批量移除错误行；不自动修正用户数据。

底部固定操作栏：`返回`、`清空输入`、`继续预览`。存在任何阻断错误时，“继续预览”禁用，并在按钮旁显示错误数量。

#### Step 3 分组预览

按 `itemId` 显示商品和 SKU 数量。预览最多展开前 10 个商品；超过 10 个时显示剩余商品数量，不继续拉长页面。安装版固定为线上模式，不显示模式分段控件。

#### Step 4 创建计划与确认闸门

点击“创建线上批次”后必须打开确认对话框，内容至少包括：

- 商品数、SKU 总数、预计耗时；
- 两阶段写入说明：临时规格提交、恢复原数据提交；
- 将保留的字段：规格文本、价格、库存、outerId、barcode、图片；
- 未知响应会暂停并转人工复核；
- 明确警示“该操作会改变线上 SKU ID”。

用户点击“继续”即完成明确确认，不再输入确认词。后端仍校验安装版线上契约、Worker 版本、登录态和商品锁。取消对话框时不得创建批次。

### 5.3 任务队列 `/tasks`

#### 工具栏

- 筛选：批次、模式、状态、时间范围、`itemId`。
- 分段视图：`全部`、`处理中`、`待复核`、`已完成`。
- 操作：暂停队列、继续队列、取消待处理项、导出当前筛选（图标按钮带提示）。

#### 列表

表格列固定为：批次、`itemId`、SKU 数、模式、阶段、进度、耗时、最后错误、更新时间、操作。进度使用 `当前步骤 / 总步骤` 和细进度条两种形式；不只显示百分比。

行操作：查看详情、暂停/继续、重试（仅 `retry_eligible`）、标记人工复核。破坏性操作必须使用二次确认；对正在写入的行不显示取消按钮，只显示“请求完成后暂停”。

#### 批量操作规则

- 批量重试只允许选择状态为 `retry_eligible` 的任务，且弹窗列出每个 `itemId`。
- 批量取消只影响 `queued`，并在完成后显示实际取消数量。
- 任何含 `needs_manual_review` 的选择都禁用“批量重试”，要求进入详情逐项确认。

### 5.4 任务详情 `/tasks/:batchId/:itemId`

页面标题显示商品 ID、批次和模式，右上角提供“返回队列”“导出脱敏审计”。

#### 阶段时间线

```text
已读取快照  ✓  04:12:01  2 SKU  快照哈希 8f…
临时提交    ✓  04:12:12  业务成功
临时回读    ✓  04:12:18  新 ID: 612… / 612…
恢复提交    ●  04:12:25  进行中
最终回读    ○  --        等待
```

时间线节点可展开查看脱敏接口路径、HTTP 状态、业务码、耗时和 `requestId`。完整请求体默认折叠，并只允许显示已脱敏字段。

#### SKU 对照区

使用三个标签页：`原始快照`、`临时提交`、`最终结果`。每个标签页的表格列为规格组合、SKU ID、价格、库存、outerId、barcode、图片缩略图。最终结果旁显示“与预期一致”或“存在差异”。

差异表按字段分行，旧值和新值并排；缺失、变化、未校验分别使用图标和文字。图片只显示 URL 的域名和缩略图，不在界面暴露签名参数。

#### 人工复核区

当状态为 `needs_manual_review` 时，页面顶部出现阻断警示：未知响应/回读差异/登录验证等原因。可选动作：

- “打开浏览器检查”：恢复同一个专属 Edge 窗口到商品页；
- “重新读取状态”：只读回读，不写入；
- “确认已完成”：需要输入备注并由后端记录；
- “从最近安全阶段继续”：仅当后端明确给出可恢复阶段时显示。

当错误码为 `channel_option_migration_required`（并兼容旧任务的 `channel_option_invalid`）且任务未发出线上写入时，人工复核区改为销售渠道迁移动作：

- 显示当次观察到的旧值 `5` 或“空值”，不得把它展示为有效选项；
- 使用二段选择呈现 `1 纯电商`与`2 商场同款`，默认不选；
- “确认渠道并重试”只提交当前任务的选择与确认，不批量处理兄弟任务；
- 说明 Worker 会重新读取页面候选后才允许预检或提交；取消保持任务原状态。

不提供“强制标记成功”按钮。

### 5.5 浏览器登录 `/browser`

此页是状态控制台，不嵌入天猫页面。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 浏览器登录                                      [打开登录窗口]   │
├───────────────────┬──────────────────────────────────────────────┤
│ Profile            │ 登录态                                       │
│ tmall-account-01  │ ● 有效                                        │
│ 本机受限目录       │ 最后检查 15:20                               │
├───────────────────┴──────────────────────────────────────────────┤
│ Worker：窗口已隐藏     Edge：有头运行         当前页面：商品编辑页  │
│                                                          [检查登录] │
├──────────────────────────────────────────────────────────────────┤
│ 验证提示 / 最近诊断                                               │
└──────────────────────────────────────────────────────────────────┘
```

首次登录或需要验证码时，点击“打开登录窗口”启动正常有头的系统 Edge 专属 Profile；登录期间 Worker 不附加 Playwright。用户点击“我已完成登录”后才建立 CDP 连接并检测状态，不读取凭据。检测成功后使用 Win32 隐藏同一窗口，浏览器进程、Browser ID、Profile 和标签页保持不变；同 Profile 已被其他进程占用时显示明确错误。

登录失效时，全局顶部状态变为“需要人工验证”，线上创建和写入操作禁用。

### 5.6 审计记录 `/audit`

筛选项：批次、`itemId`、结果、时间范围、错误码。表格显示批次、商品、原/新 SKU 映射数量、快照哈希前 8 位、最后阶段、操作者、时间。默认隐藏完整请求内容。

“导出脱敏 JSON”在导出前显示字段清单和记录数，并明确不包含 Cookie、Token、Authorization、完整图片签名 URL。导出失败时保留筛选条件并提供重试。

### 5.7 新增花型应用

`导入花型`视图由 Excel 上传区、八列字段带、批次摘要和组合预览表组成。接受 `.xlsx` 且最大 10 MB；显示工作表名、商品数、Excel 组合数、源行号和前 80 行预览。解析错误在上传区内列出并禁用主按钮，多工作表和备注语义以非阻断警告显示。

点击“创建线上批次”前展示商品数、组合数、已有组合只读核对、缺少组合新增和每商品最多一次提交的确认摘要。取消对话框不得发送 `POST /tasks`。任务队列独立筛选 `operation=add_pattern`，显示 Excel 组合数、线上已有/实际新增数量、阶段和进度；已发出写入且状态未知的任务只能人工复核，不能在列表中重试。

旧渠道 `5` 或空值的任务在队列行和详情中显示“选择销售渠道并重试”，但普通失败任务不显示渠道编辑控件。迁移弹窗必须显示商品 ID、观察到的旧值、两个现代选项和只重试当前任务的说明；确认按钮在未选择时禁用。

窗口关闭、最小化、最大化、拖动和缩放遵循工作台统一行为。模块保持挂载，因此重新打开后文件名、解析结果和组合预览仍存在；退出 Tauri 后不持久化本地文件内容。

## 6. 状态矩阵与文案

| 场景 | 顶部状态 | 页面表现 | 用户动作 |
|---|---|---|---|
| 首次启动未登录 | `需要登录` | 登录页主按钮可用，写入按钮禁用 | 打开可见登录窗口 |
| 登录检测中 | `检查中` | 骨架状态，禁用切换 Profile | 等待或取消检查 |
| 登录有效且隐藏运行 | `已登录 / 隐藏运行` | 全功能可用 | 导入或查看任务 |
| 验证码/二次确认 | `需要人工验证` | 红色阻断条，任务暂停 | 打开登录窗口完成验证 |
| Worker 断开 | `Worker 不可用` | 历史可读，创建任务禁用 | 重新连接/查看诊断 |
| 导入为空 | `就绪` | 空状态和导入按钮 | 选择文件或粘贴 |
| 导入有校验错误 | `待修正` | 错误行表格，继续按钮禁用 | 修正或删除错误行 |
| 线上待确认 | `等待确认` | 风险摘要和确认对话框 | 点击继续或取消 |
| 旧渠道待迁移 | `待人工复核` | 显示旧值和现代渠道二段选择，未选择时确认禁用 | 明确选择 `1/2` 并只重试当前商品 |
| 提交超时/未知 | `待人工复核` | 阻断警示，禁止自动重试 | 只读回读后决定 |
| 最终字段不一致 | `待人工复核` | 差异表高亮 | 打开浏览器或重新读取 |
| 无权限/业务拒绝 | `失败` | 错误码和下一步动作 | 修复登录/权限后重试 |

建议的短文案：

- 空队列：`还没有任务`，按钮 `导入清单`。
- 读取中：`正在读取商品快照`。
- 未知响应：`服务端状态不明确，已暂停写入`。
- 成功：`最终回读一致`。
- 差异：`发现 2 个字段差异，需人工复核`。

### 7.5 可组合逻辑与类型

前端至少实现以下 composable/store，名称可按项目约定调整：

- `useWorkerHealth()`：订阅 Worker 健康和登录状态。
- `useImportDraft()`：解析、校验、去重和草稿持久化。
- `useTaskQueue()`：读取任务、SSE 订阅、暂停/继续/取消动作。
- `useConfirmationGate()`：生成批次摘要并执行一次明确确认。
- `useTaskDetail()`：读取时间线、快照、差异和人工复核动作。
- `useAudit()`：分页、筛选和脱敏导出。

推荐最小类型：

```ts
type Mode = 'demo' | 'live'
type TaskStatus =
  | 'draft' | 'validated' | 'planned' | 'awaiting_confirmation' | 'queued'
  | 'reading_snapshot' | 'temp_submitting' | 'temp_verified'
  | 'restoring' | 'final_verifying' | 'succeeded' | 'paused'
  | 'failed' | 'retry_eligible' | 'needs_manual_review'

interface TaskRow {
  batchId: string
  itemId: string
  skuCount: number
  mode: Mode
  status: TaskStatus
  stage: string
  completedSteps: number
  totalSteps: number
  lastErrorCode?: string
  updatedAt: string
}

interface FieldDiff {
  field: string
  expected: string | number | null
  actual: string | number | null
  state: 'match' | 'changed' | 'missing' | 'unverified'
}
```

## 8. 交互与可访问性验收

- 所有主流程可只用键盘完成：导航、上传、筛选、对话框确认/取消。
- 焦点始终有可见环；对话框打开时焦点进入标题或第一个控件，关闭后返回触发按钮。
- 表格支持行级 `aria-label`，状态标签有文字，图片缩略图有商品/规格组合描述。
- 长 `itemId`、SKU ID 和 URL 可复制但不自动截断数据；视觉上使用中间省略并提供完整值 tooltip。
- 破坏性操作按钮使用动词+对象（如“取消 3 个待处理任务”），不使用模糊的“确定”。
- 100% 缩放和 125% Windows 缩放下不出现文字重叠或操作按钮被裁切。

## 10. 设计边界

- 本文只定义 Tauri/Vue 控制台体验，不定义天猫接口字段、Playwright 实现或 SQLite 表结构。
- 浏览器窗口是 Worker 的受控辅助界面；不在 Tauri WebView 中加载天猫登录页，也不将 CDP 端口暴露给渲染层。
- 任何接口契约变更由架构/Worker 层通过稳定的 UI DTO 和错误码传递，前端不依赖天猫页面 DOM。
