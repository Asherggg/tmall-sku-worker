# Tmall SKU Worker v0.1.25

## 激进批处理性能

- 同一线上批次最多并行处理 2 个不同商品。
- 每个商品内部仍严格执行：完整快照 -> 临时唯一规格提交 -> 新 SKU ID 回读 -> 原业务字段恢复提交 -> 最终严格回读。
- 所有 `/tmall/submit.htm` 写请求通过 Worker 级写锁串行；同一商品的未确认写入锁、未知结果人工复核和禁止自动重试规则保持不变。
- 最终回读采用 500ms、1s、2s、4s、8s 后封顶 10s 的自适应间隔，150 秒硬截止和截止点最后一次新鲜 GET 保持不变。
- 只读发布页回读可在 `window.noIcmpJson` 模型边界处停止接收 HTML；截断模型解析失败时回退到完整的 BrowserContext GET。
- 阶段耗时、累计耗时、轮询次数、传输方式和截止状态进入脱敏审计，不记录 Cookie、Token、Authorization 或完整请求体。

## 功能边界

- 线上流程只重建天猫 SKU ID，不调用 OMS，不查询或补全外部商品资料/条码，不执行国补提交。
- 唯一预期持久变化是旧 SKU ID -> 新 SKU ID；价格、规格、商家编码、现有条码、图片和其他业务字段必须恢复一致，`skuStock` 仅因平台实时变化而忽略比较。
- 登录与风险挑战仍由用户在专属有头 Edge 中完成；写入前必须验证登录态且 `navigator.webdriver === false`。
