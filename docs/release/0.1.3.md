# Tmall SKU Worker v0.1.3 线上重建版

## 版本定位

v0.1.3 是首个内置 `tmall-publish-v1` 线上执行器的安装版本。安装包启动的 Worker 默认报告 `mode=live`、`contract=configured`；源码直接运行 `npm run worker` 时仍默认演练模式，便于开发和测试。

## 线上流程

1. 使用应用专属 Edge Profile 手工登录，并执行登录态检查。
2. 按行导入商品 ID，选择“线上”，输入确认词 `确认线上重建`。
3. Worker 打开对应发布页，通过 `GlobalStore.engine.getModels('formValues')` 读取完整实时表单。
4. 校验销售渠道只允许当前页面提供的 `1` 或 `2`，不重放历史无效值。
5. 为一组销售属性生成临时唯一文本，同时清空条码、使用临时商家编码，并将行级 `skuId`、`skuOldSku`、`sourceSkuId` 置空。
6. 调用同源销售属性预检接口，再通过页面内部 `button-submit:click` 事件触发第一次 `POST /tmall/submit.htm`。该过程不是 DOM 模拟点击。
7. 重载发布页，确认每行获得正数新 SKU ID 且不等于原 ID。
8. 恢复原规格文本、价格、库存、商家编码、条码及其他 SKU 字段，保留第一次得到的新 ID，执行第二次提交。
9. 再次重载，确认新 ID 不变且业务字段与原快照一致，才标记成功。

## 停止条件

以下任一情况都会转入“人工复核”，并禁止自动重试：登录失效、风控/验证码、页面运行时契约缺失、销售渠道值不合法、预检失败、本地表单校验未通过、HTTP 或业务错误、HTTP 200 但响应无法判定、临时 ID 复用、最终 ID 变化、最终字段不一致。

线上批次启动后不会提供暂停操作：第一次写入后必须继续执行恢复和回读。任何无法确认的写入会锁定该商品，阻止新建或自动重试同商品任务，直到人工核对服务端状态。

## 审计边界

审计只保存商品 ID、阶段、接口路径、HTTP 状态、业务码、SKU ID 和脱敏字段摘要。不保存 Cookie、Token、Authorization、XSRF、完整请求体或完整商品描述。

## 安装与升级

退出旧版程序后运行 `Tmall SKU Worker_0.1.3_x64-setup.exe`。NSIS 安装向导可选择当前用户下的安装目录。升级会保留应用数据目录中的专属 Edge Profile 和任务历史。
